# НУШ Тести-гра (`nush-quiz-game`)

Генератор інтерактивних тестів-ігор НУШ. Кожна гра — один автономний `index.html` (без фреймворків, CDN і зовнішніх ресурсів), працює з `file://` і як статичний сайт (GitHub Pages).

- `games/<subject>-<grade>-<topic>/index.html` — гра. Угорі файла `GAME_CONFIG` (subject, grade, topic, questionCount, maxScore 10/12, resultsEndpoint, teacherEmail, allowRetake) і `GRADE_THRESHOLDS` (робочі пороги вчителя, не офіційні критерії).
- `games/<...>/bank.src.js` — читабельне джерело банку завдань (правильний варіант — першим).
- `tools/build-bank.js <папка гри>` — кодує банк у `index.html` (перемішує варіанти, зберігає індекс правильного). **Після кожної зміни `bank.src.js` запускайте збірку.**
- `tools/test-game.js <папка гри>` — перевірки без мережі: межі порогів обох шкал (0–100%), декодування банку, валідатор і квоти (500 спроб), `Code.gs` із заглушками.
- `tools/mock-endpoint.js [порт]` — локальна імітація веб-застосунку Apps Script (виконує справжній `Code.gs`) для перевірки відправки.
- `apps-script/` — приймач результатів (Google Таблиця + лист учителю), інструкція в `apps-script/README.md`.

## Обфускація відповідей
Правильні відповіді в `index.html` закодовані (XOR + base64), тож їх не видно відкритим текстом поруч із питанням. **Це не захист**, а лише ускладнення підглядання: учень із інструментами розробника може декодувати банк. Для контрольних робіт із високими ставками потрібна перевірка на сервері.

## Дані учнів
ПІБ, email і клас живуть лише в пам'яті сторінки та `sessionStorage` (до закриття вкладки або кнопки «Очистити дані сеансу»); не потрапляють в URL, консоль чи `localStorage`. Єдиний мережевий запит — POST результату на `resultsEndpoint`.
